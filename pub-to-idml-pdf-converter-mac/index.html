.pub to IDML and PDF converter for Mac

PubFile opens Microsoft Publisher files on your Mac and gives you back editable IDML documents, PDFs, and a plain-language report on each one. It runs entirely on your Mac. The free version converts three files at full quality, so you can judge the result on your own documents before spending anything.

How it works

  1. Open a .pub file: File ▸ Open…, drag it onto the window, or double-click it in Finder. Open several at once; each gets a tab.
  2. See every page rendered. View ▸ Show Page Thumbnails (⌥⌘T) adds a sidebar. In Finder, press Space for a Quick Look preview without opening the app.
  3. Read the report in the inspector (⌥⌘I): fonts used and which were substituted, how much of each story was placed on each page, and any object that could not be converted, shown next to the page. The preview is the conversion.
  4. Export: File ▸ Export as PDF… (⌘E) or Export as IDML… (⇧⌘E). With Pro, File ▸ Convert All Open Documents… (⌘B) writes an .idml, a .pdf and a report for every open file into one folder.
  5. Open the IDML in Affinity (free), Affinity Publisher 2 or InDesign and keep editing.

Multi-page documents: the part everything else gets wrong

Publisher newsletters usually use linked text boxes: one long story that flows from a box on page 1 into a box on page 3, and so on. The open-source parser that LibreOffice and the existing Mac .pub apps rely on (libmspub) has never implemented that link. Instead it puts the entire story into every linked box, so page 1, page 2 and page 3 each show the whole article, and the last page comes out empty. The bug has been open in LibreOffice's tracker since 2013 (bug 67299), and it is the most common one-star complaint on the incumbent Mac app.

PubFile is built on the same open-source parser, with that link implemented: the story is split across the boxes the way Publisher laid it out, and linked boxes stay linked in the IDML. The parser changes are published under the same licence.

Our acceptance test was the exact 4-page document attached to that 2013 bug report. It is the file in the screenshot on the home page: the story flows from page 1 to page 4 with no duplication, and the report lists what did not survive.

What comes out

IDML (InDesign Markup Language)

A documented, zipped-XML page-layout format. Pages, text frames with live text and paragraph and character formatting, linked text boxes reconnected, pictures extracted at original resolution into a Links folder, shapes, colours and tab stops. Opens in:

  • Affinity (2025 release, free) and Affinity Publisher 2 / 1.8+, confirmed by Affinity.
  • Adobe InDesign CS4 and later.

Affinity's own note on IDML import applies: page structure, text frames and basic styles are preserved, "some advanced formatting, like GREP styles, anchored objects, and tables, may require manual adjustment." In 1.0, tables render in the preview and PDF but are not written to the IDML; the report says so when a file has them.

PDF

One PDF per file, vector text (searchable, selectable), images embedded at original resolution, page size as set in the document.

Fidelity report

Shown in the inspector for every file you open, and saved as <name>.report.txt and .json next to Pro exports. It is not a font inventory dressed up as a report; it is a check. It lists:

  • Pages detected and pages written.
  • For each story and page, how many characters were placed and any text that did not fit.
  • Fonts referenced, which are installed on your Mac, and what was substituted.
  • Objects the converter could not handle (WMF/EMF clip art, tables in IDML, embedded OLE objects, certain WordArt warps and 3-D or shadow effects).
  • A single verdict per file: clean, check, or problems, with plain-English notes.

Supported files

  • Publisher 98, 2000, 2002, 2003, 2007, 2010, 2013, 2016, 2019, 2021 and Microsoft 365 (.pub).
  • Publisher 97 and earlier: not supported, the format is different and no open parser exists for it. If you have these, export them from a working Publisher while you can.
  • Password-protected files: not supported.

What PubFile is not

  • It is not Publisher for Mac. You cannot edit .pub files in it, and it does not save .pub files. It gets your content out into formats that have a future.
  • It is not a cloud service. There is no upload, no account, no analytics, and it works offline. Privacy
  • It is not perfect. Publisher has thirty years of features; some (WMF clip art, tables in IDML, embedded OLE objects, certain WordArt effects) will not convert cleanly in 1.0. The report will tell you which ones, on which page.
